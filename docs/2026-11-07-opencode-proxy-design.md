# opencode-proxy: рабочее состояние

Дата: 2026-11-07

## Зачем

Claude Desktop (профиль «opencode») уже ходит в локальный прокси `http://127.0.0.1:4000`, а прокси переписывает модель на модели OpenCode Go. Но сейчас он форсит одну модель через `model.txt`, падает при перегрузке upstream, не запускается сам и почти ничего не пишет в лог.

## Цели

1. **Сервис.** Прокси живёт как launchd-агент: поднимается при логине, переживает падение, логи не теряются.
2. **Логи в файл.** Одна структурированная строка на запрос: модель до/после, статус, длительность, токены, число ретраев. Ротация, чтобы файл не рос вечно.
3. **Ручной маппинг.** Все доступные модели OpenCode Go (сейчас 21 из 30 в каталоге) доступны в пикере desktop-приложения, каждая уходит на свой upstream id.
4. **429 `prefill_cap_refused`.** Прокси сам ждёт и повторяет; до UI перегрузка не доходит.
5. **Пульт по REST.** Логи и маппинг моделей меняются на ходу, без рестарта и без правки файла руками.
6. **Навык генерации конфига.** Список моделей живёт в одном `models.json`, конфиг для Claude собирается из него, а не правится руками.

## Non-goals

- Автодискавери через `/v1/models` (`modelDiscoveryEnabled: true`) — не сейчас; структура конфига не должна ему мешать.
- Роутинг по родным эндпоинтам (`/openai/...`, `/google/...`). Console переводит, всё гоняем в `/anthropic`.
- CLI (`~/.claude/settings.json` смотрит прямо на opencode.ai). Отдельная задача.

## Anti-goals

- Прокси молча подменяет модель, которую пользователь выбрал руками.
- 429 (или любой 4xx/5xx upstream) доходит до интерфейса без попытки ретрая.
- В логе нельзя понять, какая модель реально отвечала и сколько это заняло.
- Сервис умирает, и никто этого не видит.

## Текущее состояние (факты)

- `main.go` — один файл, ~170 строк, HTTP-прокси, стримит SSE.
- Цепочка маппинга: `aliases.txt` → `model.txt` → хардкод `modelMap`. `model.txt` стоит выше хардкода и перетирает всё: в логе 1097 из 1142 запросов ушли на `deepseek-v4.1-flash`, включая `claude-haiku-5-5`.
- 429 — не квота: `{"type":"rate_limit_error","message":"Upstream request failed: [prefill_cap_refused] the cell is at capacity; retry shortly (after 30 s)"}`. Тот же запрос через 30 с проходит.
- Лог пишется в `proxy.log` и stderr, без длительности, токенов и ротации.
- Desktop-конфиг `~/Library/Application Support/Claude-3p/configLibrary/fa30e34e-….json`: `inferenceGatewayBaseUrl: http://127.0.0.1:4000`, `modelDiscoveryEnabled: false`, одна модель `claude-v4.1-flash`.
- Формат записи модели в приложении (из `ion-dist.asar`): `name`, `labelOverride`, `behavesAs`, `anthropicFamilyTier` (opus/sonnet/haiku/fable/mythos), `supports1m`, `prefer1m`, `maxEffort` (low/medium/high/xhigh/max), `isFamilyDefault`.
- `behavesAs: "deepseek-v4.1-flash"` в текущей записи приложение игнорирует (не Claude-id), поэтому effort падает в `low`.
- В Auto-режиме приложение зовёт `claude-sonnet-5` как классификатор безопасности, даже если модели нет в списке.

## Решение

### 1. Конфиг прокси: один `config.json`

Заменяет `model.txt` + `aliases.txt` + хардкод. Перечитывается по mtime, правки — без рестарта.

```json
{
  "listen": "127.0.0.1:4000",
  "upstream": "https://opencode.ai/inference/go/anthropic",
  "session_fallback": "my-session-1",
  "log": {
    "file": "~/opencode-proxy/proxy.log",
    "level": "info",
    "max_mb": 10,
    "keep": 5,
    "capture": {
      "request_headers": false,
      "request_body": false,
      "response_headers": false,
      "response_body": false
    },
    "max_body_bytes": 65536
  },
  "models": {
    "default": "deepseek-v4.1-flash",
    "background": "deepseek-v4.1-flash",
    "aliases": {
      "claude-v4.1-flash": "deepseek-v4.1-flash",
      "claude-v151-flash": "deepseek-v4.1-flash",
      "claude-sonnet-5": "deepseek-v4.1-flash"
    }
  },
  "retry": {
    "max_attempts": 5,
    "first_wait_ms": 2000,
    "multiplier": 2,
    "max_wait_ms": 15000,
    "total_budget_ms": 60000
  },
  "admin": { "enabled": true, "token": "" },
  "connect_timeout_seconds": 15
}
```

`models.default` — что подставлять, если id неизвестен. `models.background` — что подставлять фоновым вызовам Claude Code. `models.aliases` — явные псевдонимы.

`log.capture` — четыре независимых переключателя, любая комбинация. Каждый включается и выключается отдельно; по умолчанию всё выключено, потому что в телах лежит код.

### 2. Резолвинг модели

Порядок, первый сработавший выигрывает:

1. Точное совпадение в `models.aliases` (без учёта регистра).
2. Id вида `claude-<X>`, где `<X>` — известный native id: отдаём `<X>` в нижнем регистре. Так `claude-GLM-5.3-Flash` превращается в `glm-5.3-flash`, а `claude-Kimi-K3.1-Pro` — в `kimi-k3.1-pro`.
3. `claude-haiku-*` — `models.background`. Стоит **выше** native-проверки намеренно, иначе `claude-haiku-5-5` (он есть в каталоге OpenCode) уходил бы в passthrough, и фоновые вызовы Claude Code никогда бы не попадали на дешёвую модель.
4. Id уже в реестре native-моделей — оставить как есть.
5. Иначе — `models.default` (сюда же попадает `claude-sonnet-5` из Auto-режима).

Регистр не важен на входе, но в upstream всегда уходит lowercase.

Следствие правила 3: чтобы выбрать OpenCode-шный Haiku в пикере отдельно, запись должна называться `claude-claude-haiku-5-5` — тогда правило 2 сработает раньше и отдаст `claude-haiku-5-5`, а служебные вызовы Claude Code по-прежнему пойдут в `background`.

Подмена всегда пишется в лог с причиной. Модель, выбранная в пикере, никогда не подменяется на другую.

### 3. Ретраи

- Ретраим 429 и 5xx **до** записи заголовков ответа (тело уже прочитано в память, запрос повторяем).
- Ждём **меньше**, чем советует upstream — он пишет «after 30 s», но по опыту ячейка освобождается раньше.
- Лесенка: 2 с, 4 с, 8 с, 15 с, 15 с — до 5 попыток, суммарно не дольше 60 с. Параметры в `retry`.
- Если upstream прислал заголовок `Retry-After` — уважаем его, но не больше `max_wait_ms`.
- Текст «after N s» из тела парсим только для лога, на задержку не влияет.
- Небольшой джиттер (±20%), чтобы параллельные запросы не били в одну секунду.
- Каждая попытка — отдельная строка в логе с номером и временем ожидания.
- Если все попытки исчерпаны — отдаём последний ответ как есть.
- `count_tokens` тоже ретраится.

Отдельно: одинаковые параллельные `count_tokens` (в логе бывает по 8 штук с одним телом в одну секунду) кэшируются по хешу тела на 60 с — снимает лишнюю нагрузку с ячейки.

### 4. Логи

Одна строка на событие, key=value:

```
2026-11-07T12:32:01+03:00 INFO  req=a1b2c3 POST /v1/messages session=739b29 model=claude-v4.1-flash->deepseek-v4.1-flash why=alias status=200 dur=1.24s in=1834 out=412 cache_read=51200 attempt=1
```

- `why` — источник подмены: `alias` / `background` / `auto` / `default` / `native`.
- Ротация по размеру: при превышении `max_mb` файл уезжает в `.1`, старые удаляются после `keep` штук.

**Полная запись по требованию.** Четыре независимых переключателя в `log.capture`: `request_headers`, `request_body`, `response_headers`, `response_body`. Любая комбинация, каждый включается сам по себе.

Захваченное не пишется в основной лог — иначе его нельзя будет читать построчно. Оно уходит в `<logfile>.jsonl`, по одному JSON-объекту на запрос, с тем же `req`:

```json
{"req":"a1b2c3","ts":"2026-11-07T12:32:01+03:00","request_headers":{...},"request_body":"...","response_headers":{...},"response_body":"..."}
```

- Тела обрезаются по `max_body_bytes` (по умолчанию 64 КБ), с пометкой `truncated: true`.
- `response_body` для стриминговых ответов — это перехваченный SSE-поток; пишется после закрытия стрима.
- Файл `.jsonl` ротируется по тем же правилам.
- Правка `capture` подхватывается по mtime, как и остальной конфиг — рестарт не нужен.

### 5. Сервис

`~/Library/LaunchAgents/ai.opencode.proxy.plist`:

- `RunAtLoad: true`, `KeepAlive: true`
- `StandardOutPath` / `StandardErrorPath` — в тот же каталог
- `WorkingDirectory` — каталог проекта
- запуск `opencode-proxy -config ~/opencode-proxy/config.json`

Плюс `make install` / `make uninstall`, чтобы ставить и снимать одной командой.

### 6. Конфиг приложения: 32 записи

В `inferenceModels` добавляются все модели из списка OpenCode Go. Запись:

```json
{
  "name": "claude-GLM-5.3-Flash",
  "labelOverride": "GLM 5.3 Flash",
  "behavesAs": "claude-sonnet-5",
  "maxEffort": "medium"
}
```

Правило имени: `claude-` + native id в том регистре, в каком хочется видеть в пикере. Прокси снимает префикс и приводит к нижнему регистру.

- `name` — то, что видно в пикере и уходит в прокси.
- `labelOverride` — человеческое имя в пикере; без него приложение отформатирует id само.
- `behavesAs` — Claude-модель, чьи effort-уровни и лимиты наследуются. Префикс `claude-` здесь ничего не даёт: `claude-GLM-5.3-Flash` приложение всё равно не опознаёт, поэтому `behavesAs` обязателен.
- `supports1m` — только там, где 1M реально поддержан.

### 7. Пульт управления по REST

Прокси отдаёт админ-API на том же порту, под префиксом `/admin/`. Этот префикс никогда не форвардится наверх: клиент ходит только в `/v1/*` и `/api/hello`.

| метод | путь | что делает |
|---|---|---|
| `GET` | `/admin/status` | здоровье, uptime, апстрим, текущая версия конфига, счётчики запросов/ретраев/429 |
| `GET` | `/admin/config` | весь конфиг как есть |
| `PATCH` | `/admin/config` | частичное обновление: `log.capture`, `models.*`, `retry.*` |
| `GET` | `/admin/log/capture` | текущие четыре флага |
| `PUT` | `/admin/log/capture` | включить/выключить любой набор флагов |
| `GET` | `/admin/models` | реестр native-id + таблица алиасов + как резолвится каждый id |
| `PUT` | `/admin/models/aliases` | заменить таблицу алиасов целиком |
| `POST` | `/admin/reload` | перечитать `config.json` с диска |
| `GET` | `/admin/session-cost?session=<id>` | стоимость по сессии: `usd` (сумма `allowance`), `list_usd` (сумма `list_cost`), число запросов, окно времени и разбивка по моделям. Неизвестная сессия — 200 с нулями |

Примеры:

```bash
curl -X PUT localhost:4000/admin/log/capture -d '{"request_headers":true,"response_body":true}'
curl -X PUT localhost:4000/admin/models/aliases -d '{"claude-GLM-5.3-Flash":"glm-5.3"}'
curl -X PATCH localhost:4000/admin/config -d '{"models":{"default":"glm-5.3-flash"}}'
```

Правила:

- Правки применяются атомарно — в полёте запросы не страдают.
- Правка через API **пишется в `config.json`**, чтобы пережить рестарт. Внешняя правка файла подхватывается по mtime; чья правка новее, тот и выиграл.
- Ответы отдают эффективное состояние после применения, а не то, что прислали.
- Всё, что не `/admin/*`, идёт наверх как раньше — включая неизвестные пути.
- `admin.enabled: false` выключает раздел целиком (404).
- Если задан `admin.token` — требуется заголовок `X-Admin-Token`, иначе `401`.

Ограничение: слушаем только `127.0.0.1`, так что снаружи машины пульт недоступен. Это осознанно — команды меняют, куда уходят твои промпты.

### 8. Навык генерации конфига

Список моделей нужен в двух местах: прокси (чтобы знать native id) и desktop-приложение (записи `inferenceModels`). Держать его в двух местах руками — ровно та ошибка, что привела к текущему бардаку. Поэтому источник правды один — `models.json` в проекте, а конфиги для Claude генерируются из него.

```json
{
  "models": [
    {
      "id": "glm-5.3-flash",
      "picker": "claude-GLM-5.3-Flash",
      "label": "GLM 5.3 Flash",
      "behaves_as": "claude-sonnet-5",
      "max_effort": "medium",
      "supports_1m": false,
      "monthly_limit_usd": 60,
      "pricing": { "input": 0.15, "output": 0.50, "cache_read": 0.03 }
    }
  ]
}
```

Из одной записи получаются: алиас прокси (`picker` → `id`), запись пикера (`name`, `labelOverride`, `behavesAs`, `maxEffort`, `supports1m`) и ставки для оценки стоимости в `/admin/status`.

Навык `claude-config` — это инструкция для Claude Code, а не отдельный бинарник. Он умеет:

1. **Импортировать список.** Пользователь вставляет таблицу моделей из консоли OpenCode — навык обновляет `models.json`: добавляет новые, помечает пропавшие, не трогает руками настроенные поля (`label`, `behaves_as`).
2. **Сгенерировать конфиг приложения.** Собирает `inferenceModels` из `models.json`, находит активный профиль в `configLibrary` (по `appliedId` из `_meta.json`), делает бэкап и записывает. Показывает diff.
3. **Проверить.** Уникальность id, валидность `behavesAs`/`maxEffort`/`anthropicFamilyTier`, что `picker` начинается с `claude-`, что каждый `id` есть в списке OpenCode Go.
4. **Сгенерировать блок для CLI** — `ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL` и список моделей для `~/.claude/settings.json`, если попросят.

Навык ничего не пишет без показа diff'а и не трогает чужие ключи в профиле.

### 9. Что реально даёт API OpenCode (проверено)

**Каталог моделей.** `GET https://opencode.ai/inference/go/v1/models` — публичный, без авторизации, сейчас отдаёт **30** моделей (в документации перечислено 32; `mimo-v2.5` и `mimo-v2.5-pro` из каталога уже убраны). Для каждой: `id`, `name`, `limit.context`, `capabilities.tools.supported`, `capabilities.reasoning.effort` (список поддерживаемых уровней), `cost.text` (input / output / cache read), `api` (родное семейство).

Отсюда `models.json` генерируется целиком — руками переносить 30 записей не нужно.

**Трансляция между API работает.** Проверил живьём: `glm-5.3-flash` (родное — chat completions), `gemini-4-argon` (родное — Google), `kimi-k3`, `qwen3.7-plus` — все отвечают корректным Anthropic-ответом через `/go/anthropic/v1/messages`. Значит роутинг по семействам не нужен, всё идёт в один эндпоинт.

**`x-opencode-session` обязателен.** Без него upstream отдаёт `{"type":"error","error":{"type":"MissingSessionID",...}}`. Прокси этот заголовок уже ставит — закрепить тестом, чтобы не потерять при рефакторинге.

**Стоимость приходит в каждом ответе.** В `usage` лежит блок `opencode`:

```json
"opencode": { "billing_source": "go", "list_cost": 0.00000395, "allowance": 0.00000395,
              "tokens": { "input": 13, "output": 4, "reasoning": 4, "cache_read": 0 } }
```

`list_cost` — цена по прайсу, `allowance` — сколько списалось с месячного лимита. Прокси пишет обе цифры в лог и копит сумму в `/admin/status`: видно расход по каждой модели против её месячного лимита.

**Доступность зависит от региона.** Прогнал probe по всем 30:

| статус | модели |
|---|---|
| работают | glm-5.3, glm-5.3-flash, glm-5.2, deepseek-v4.1-flash, deepseek-v4-pro, kimi-k3, kimi-k3.1-pro, kimi-k2.7-code, qwen3.8-max, qwen3.8-flash, qwen3.7-plus, minimax-m3, minimax-m3.1-flash, mimo-v2.6-flash, mimo-v2.6-pro, hy3, hy4, hy4-preview, step-5-preview, gemini-4-argon, claude-haiku-5-5 |
| нет в регионе | gpt-6-luna, gpt-5.6-luna, grok-4.7, muse-spark-1.2-contributor, muse-spark-1.3-contributor, beam-free, crouton-alpha-free |
| эндпоинт лежит | longcat-2.0 |
| нужен consent на обучение | iceman-contributor-free |

Поэтому в `models.json` есть поле `available`, а навык обновляет его прогоном probe. В пикер попадают **только доступные** — недоступные скрываются целиком, без серых пунктов и без пометок: серый пункт в пикере выглядит как поломка приложения, а не как региональное ограничение.

**Уровни effort у всех разные.** glm-5.3 — low/high/max, glm-5.2 — high/max, kimi-k3 — только max, hy4 — none/high, deepseek-v4.1-flash — low/high/max. Приложение умеет понижать до ближайшего поддерживаемого, но `maxEffort` в конфиге надо брать из каталога, а не ставить «medium для всех».

## Решения, принятые мной (можно оспорить)

- **`name` = `claude-<native id>`.** Выбран пользователем. Даёт пикеру единый вид и отдельное пространство имён: всё с префиксом — виртуальные id, всё без — native passthrough. Цена: 32 записи в `aliases`-таблице реестра, которые надо держать в синхроне со списком моделей.
- **`background` = `deepseek-v4.1-flash`.** Фоновые вызовы дешёвые, а лимит у Flash $100/мес.
- **`behavesAs` = `claude-sonnet-5`, `maxEffort` = `medium`.** Консервативно: даёт нормальные effort-уровни, но не шлёт `max`, который open-модели могут не понять. Если upstream начнёт ругаться на `thinking` — прокси вырезает поле.
- **Конфиг один, JSON.** Три источника правды (`model.txt`, `aliases.txt`, хардкод) — главная причина текущего бардака.
- **Кэш `count_tokens` 60 с.** Дешево и снимает половину пикового трафика.
- **Ретраи раньше, чем советует upstream.** 2 с на первой попытке вместо 30 с: ячейка обычно освобождается быстрее, а лишние 429 в логе видны и безвредны. Потолок ожидания — 15 с на попытку, 60 с суммарно.
- **Захват трафика — в отдельный `.jsonl`.** Основной лог остаётся построчным и грепаемым; тела и заголовки коррелируются по `req`.
- **Админка на том же порту, префикс `/admin/`.** Отдельный порт не нужен, а префикс гарантированно не пересекается с путями Anthropic API, которые уходят наверх.
- **`models.json` — единственный источник правды о моделях.** Генерируется из `GET /inference/go/v1/models` (id, контекст, effort, цены) плюс `available` из probe. Прокси читает его для native id и алиасов, навык — для генерации конфига приложения. Иначе список неизбежно разъедется.
- **В пикер только доступное.** `available: false` не попадает в `inferenceModels` — иначе пользователь выбирает модель и получает `RegionError` вместо ответа.
- **`maxEffort` берётся из каталога.** У каждой модели свой набор уровней; общий «medium для всех» даст либо отвергнутый параметр, либо понижение без предупреждения.
- **Стоимость логируем из ответа.** `usage.opencode.list_cost` и `allowance` пишутся в строку лога и копятся в `/admin/status`.

## Что осталось решить

Из ревью документа остались три технических вопроса, которые решаются проверкой, а не разговором:

- **Сколько desktop-приложение терпит до таймаута.** Ретраи держат соединение без единого байта. Бюджет 60 с взят из наблюдения, что клиент сам повторил запрос через 30 с. Если таймаут окажется меньше — придётся отдавать SSE-заголовки и heartbeat раньше.
- **Умеет ли upstream отдать ошибку уже внутри стрима.** Если да, ретрая «до заголовков» недостаточно: придётся подсматривать первый SSE-ивент перед тем, как зафиксировать ответ.
- **Нужно ли подчищать `thinking` и effort под конкретную модель.** Каталог даёт точный список уровней, так что «приводить к ближайшему поддерживаемому» теперь можно честно. Вопрос — делать это в прокси или доверить приложению.

Мелочи, которые решаю сам: `supports1m` (по `limit.context` из каталога), поведение при битом конфиге (держим последний рабочий), что `HEAD /api/hello` не ретраится.
